## Notes

- Timing comes from the providers that served the trace (model time per call), not from the GPUs being sized; the profile carries the shape of the work — context growth, reuse, gaps, tool time — not latency.
- The KV working set assumes contexts stay resident from one call to the next for up to the cache lifetime (300 s). Offloading to CPU memory or storage lowers the GPUs it needs and adds reload time.
- The flat row is how most sizing is done today: it overstates prefill (it re-prefills the whole prompt every call) and understates memory (it only counts in-flight requests).
